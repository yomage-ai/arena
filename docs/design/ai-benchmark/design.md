# AI 作品测评站 · 设计方案

版本：v1.0 · 2026-09-05 · 状态：初版方案与交互示意。

> 这是实施前的设计快照。现在已收录三个 GPT6-Astra-xhigh 作品和三个 GPT5.6-sol-max 作品，原件统一归档在 `results/`；当前目录和操作方式以 [网站使用说明](../../website.md) 为准。

建议做一个按项目组织的 AI 作品展厅：访客打开首页，选择题目，查看不同 AI 的生成结果，再打开完整 HTML 体验。第一版采用静态首页、作品清单和独立作品文件；保留原始提示词与生成条件，让展示逐步成为可追溯的测评。

## 1. 服务谁，解决什么

面向你本人、观看测评的观众，以及拿同一题目比较 AI 结果的人。典型场景是看完某个 AI 的候鸟迁徙页面，马上想体验另一个 AI 如何完成同一题目。

核心价值：同一道题的提示词、生成条件和可运行结果集中在一起，访客能自行体验差异。

核心动作：选择项目 → 打开对应 AI 的作品。产品属于作品浏览与体验型网站。成功标准是：新访客能在两次主要点击内，从首页进入指定项目的一份作品，并且能知道它由什么模型、按什么条件生成。

已确认需要项目选择、AI 结果选择、独立 HTML 跳转。暂按你手动收集和发布作品、访客免登录浏览来设计。当前目录已发现 `候鸟-MIGRATION.html` 和 `植物大战僵尸.html`；未发现自行车作品，其名称先记为“自行车动效（题目待定）”。现有两份文件的模型、原始提示词和生成轮次待补，不能推定它们已经满足同题测评条件。

## 2. 页面怎么组织

首页直接展示项目与结果，默认选中第一个已有作品的项目。左侧是项目列表，右侧是当前项目说明与 AI 结果卡片，不增加进入内容之前的欢迎页。

| 区域 | 显示内容 | 主要操作 |
| --- | --- | --- |
| 顶部 | 站点名“同题实验室”、测评规则入口 | 查看测评方法 |
| 项目列表 | 候鸟迁徙、植物大战僵尸、自行车动效；已收录数量 | 切换题目 |
| 项目介绍 | 一句话目标、考察点、提示词版本 | 查看／复制完整提示词 |
| AI 结果卡片 | 封面、产品与模型版本、轮次、可用状态、简短说明 | 打开作品、查看生成记录 |
| 补充信息 | 设备条件、已知问题、人工备注 | 辅助理解结果 |

卡片固定同等尺寸，使用相同规则显示封面与模型信息；初期不按分数排名。默认只展示一个指定轮次，更多轮次可展开。手机上项目列表变成顶部横向按钮，作品卡片单列显示。基础组件包括页面容器、项目按钮、结果卡片、状态标签、原生链接、提示词详情面板和空状态；现阶段用原生 HTML 即可。

页面层级：测评首页包含项目选择、项目介绍、AI 结果和提示词／生成记录；AI 结果链接到独立作品页；测评规则是首页内的补充阅读入口。图文版提供对应的信息结构图。

主要体验路径：打开首页 → 选择“候鸟迁徙”（第 1 次点击）→ 点击某模型卡片上的“打开作品”（第 2 次点击）→ 新标签页体验 → 回到保留选择状态的首页 → 打开另一份结果。默认项目只需一次点击即可打开作品。

“查看记录”是旁支，在当前页展开；无需先看记录才能体验。首页用 `?project=migration` 保存项目选择，刷新和分享后恢复，浏览器前进／后退同步选择；无效项目 ID 回到默认项目并说明原因。

## 3. 让“相同提示词”有依据

同一段用户提示词不必然意味着全部生成条件相同。每道题要固定提示词版本与原文；每个结果绑定该版本，并记录产品、准确模型版本、日期、可见参数、工具／联网权限、可用素材、生成预算与人工干预。

建议先约定：同题使用相同可见提示词与素材，分别记录“一次生成”和“迭代修复”。产品隐藏的系统提示词无法保证相同，应写明不可见；无法获知的参数记为“未记录”。不要用补写的示例提示词冒充历史原文。

采用“项目 → 提示词版本 → 多个模型结果 → 各自独立尝试”的关系。每次独立尝试有自己的 run ID；修复另存一份并通过 parentRunId 关联，保留原始 HTML、追问与修改说明。提示词改动则新增版本，不能与旧版本混成同题成绩。

| 概念 | 最小记录 |
| --- | --- |
| 项目 | id、标题、说明、分类、固定展示顺序 |
| 提示词版本 | id、项目 id、原文／文件路径、共用素材与规则 |
| 生成结果 | id、项目 id、提示词版本 id、产品／模型、run ID、原始或修复版、入口路径、文件可用状态 |
| 生成条件 | 日期、工具权限、可见参数、生成预算、人工干预；未知项用 null |
| 展示与检查 | 封面路径、运行检查结果、设备条件、已知问题、人工备注 |

第一版先记录“能否打开、核心功能是否完成、交互是否可用、视觉呈现、适配情况”。功能按题目列检查项，视觉附人工描述。没测试显示“未测试”；生成失败与未收录分开记录；只运行过一次就写“一次样本”，不推导稳定排名。

## 4. 大概要怎么实现

运行链路：浏览器加载首页 → 读取作品清单 → 按项目筛选结果 → 使用结果中的入口路径创建普通链接 → 浏览器独立加载作品及其资源。无需让 AI 重新生成页面，也无需在浏览时调用模型 API。

推荐先用 HTML、CSS、少量 JavaScript 实现。当前项目已有原生 HTML 与 Node 构建脚本，没有首页框架需求；新增一个独立 `site/` 发布目录，现有两个项目继续按各自方式产出作品。

建议目录如下，路径仅为实施约定，尚未创建这些生产文件：

```text
site/
  index.html
  catalog.json
  assets/                  首页样式、脚本和封面
  prompts/
    migration-v1.txt
  works/
    migration/
      model-a/
        run-01/
          index.html
          assets/          多文件作品才需要
    pvz/
      model-a/
        run-01/
          index.html
  404.html
```

单文件作品复制到对应 `run-01/index.html`；多文件作品复制完整目录，保留内部相对路径，不能只取入口 HTML。用稳定的英文 ID 组织路径，中文只作为展示名称。每个版本放独立目录，不覆盖旧作品。

清单负责描述和定位作品，例如下面是一条**虚构的结构示例**，不是当前作品的真实模型或生成记录：

```json
{
  "id": "migration-model-a-run-01",
  "projectId": "migration",
  "promptVersionId": "migration-v1",
  "modelLabel": "AI A · 准确版本待填写",
  "runId": "run-01",
  "variant": "original",
  "entry": "./works/migration/model-a/run-01/index.html",
  "availability": "available",
  "validation": "untested",
  "generatedAt": null
}
```

首页读取 `catalog.json` 后，通过 `projectId` 筛选，封面与文字生成卡片，`entry` 用于链接。模型未知的现有文件用“来源待补”展示，缺失元数据用 null，不塞入猜测。清单内容按文本渲染，入口只接受站内发布路径；不要把任意查询参数直接作为作品地址。

打开方式默认使用原生链接，新标签页加 `rel="noopener"`，首页保留项目选择。首页只加载封面，不同时运行所有作品，因此不会让多个游戏争抢音频或渲染资源。第一版不向原始作品注入导航栏，避免改变被测内容。

`catalog.json` 的读取需要 HTTP(S) 服务；正式网站自然满足，本地可从项目根目录运行 `python3 -m http.server 8776 --bind 127.0.0.1`，访问 `/site/`。图文设计稿采用内联示例数据，可直接离线打开；其中现有作品链接依赖它与项目根目录保持当前相对位置。

### 发布与更新

一次接入的步骤是：保存原始输出和生成记录 → 放入独立作品目录 → 填写清单 → 添加封面 → 在本地核对页面、资源和目标设备 → 上传 `site/` 发布目录 → 检查线上入口和作品链接。以后每增加一个 AI 结果，重复这条流程即可。

可使用 Cloudflare Pages 这类静态托管。官方支持普通 HTML 网站，也支持直接上传预先准备好的静态文件；频繁更新时可选择 Git 集成。来源：[静态 HTML 托管](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/)、[直接上传](https://developers.cloudflare.com/pages/get-started/direct-upload/)。

只发布整理后的 `site/` 内容，不直接上传整个工作目录。当前目录还有制作中间文件和测试材料；发布包应有明确边界。若访问者主要在中国大陆，上线前用目标网络实测入口、作品及外部资源速度，再决定托管与域名，不预设某个平台一定最快。

### 与作品行为有关的边界

| 情况 | 处理 |
| --- | --- |
| 模型尚未提交结果 | 显示“未收录”，不给出无效链接 |
| 文件已保存，但运行报错 | 标“运行异常”，展示问题记录，保留原始产物 |
| 路径失效或缺少资源 | 发布前检查入口与资源；线上 404 提供回首页入口，不伪装成加载成功 |
| 缺少模型／提示词记录 | 可以体验，标“来源待补”；补齐前不计入正式同题结论 |
| 音效／全屏需要用户操作 | 原作品内点击开始；按相同浏览器与视口条件体验 |
| 存档相互影响 | 独立路径不隔离 localStorage；检查存储 key 是否重复，必要时用独立来源托管，不静默改原始样本 |
| 未来需要并排体验 | 在独立作品来源上设计 iframe 预览，并保留完整页面入口；同一视口与同一测试条件比较 |

选择完整页面体验，是考虑到当前作品包含音频、全屏或本地存档。iframe 会引入尺寸和权限差异；尤其同源页面同时设置 `allow-scripts` 和 `allow-same-origin` 不能视为可靠隔离。参见 [MDN iframe 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)。新标签页也不等于隔离站点存储；第一版假定由你手动审核并收录作品，若开放他人上传，再设计独立来源和发布审核。

## 5. 分几步做

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 第一版：能看能体验 | 首页、项目选择、AI 卡片、提示词／条件展示、静态清单、独立作品链接、手机布局 | 两个现有作品能进入，空项目说明清楚，部署后链接与资源可用 |
| 第二版：方便比较 | 同题版本过滤、两份作品并排、人工评语或本地笔记 | 明确视口差异与测试条件；本地笔记标明仅存当前浏览器 |
| 第三版：按需扩展 | 公开评分、访客投票、上传管理、自动执行测评 | 有实际需求后增加后端、持久化与管理权限 |

估算：在素材和元数据齐备、由一名熟悉前端的开发者制作、仅包含第一版功能的前提下，整理作品半天，首页与清单一天，适配／验证／部署半天到一天，合计约 2–3 个工作日。这个估算不包含生成新作品、补找历史记录和修复各个 AI 作品。

## 6. 验收与待补信息

验收应覆盖：进入首页有可选项目与可用结果；切项目时说明、提示词和作品列表同步；每个 AI 结果打开自己的文件；查询参数能恢复项目，非法参数有回退；未收录不会产生死链；原作品音效、全屏与存档按预期运行；手机布局不遮挡入口；同题结果绑定正确的提示词版本；从实际部署地址打开的资源无缺失。

开始正式接入前需要补齐的资料是：准备测哪些 AI／模型版本；现有两份作品对应的生成工具与原始提示词；一次生成与允许修复的测评规则；自行车题目的准确名称和需求。它们不影响先实现首页、清单和跳转骨架。

本次交付为本文件与 `design.html` 图文阅读版。图文版包含可切换项目、查看记录、打开现有两个作品的局部原型，AI A／AI B 是未收录占位，不表示已有实际测评结果；这不是已经上线的完整站点。

本次已完成脚本语法、文档锚点、控件关联和本地作品路径的静态检查。浏览器自动预览因本地文件 URL 被策略阻止而未完成，因此项目切换、跳转、窄屏布局和实际视觉效果尚未经过浏览器验收。`build-design.py` 用于从 Markdown 正文与现有截图重新生成同版本 HTML 阅读版。
